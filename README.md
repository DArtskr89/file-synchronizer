# Сервис синхронизации файлов с Яндекс Диском

Консольное Python-приложение автоматически синхронизирует файлы из выбранной
папки на компьютере с отдельной папкой на Яндекс Диске. Программа выполняет
первую синхронизацию сразу после запуска, а затем повторяет проверку с заданным
интервалом.

## Возможности

- загрузка новых локальных файлов на Яндекс Диск;
- перезапись облачной копии после изменения локального файла;
- удаление облачной копии после удаления локального файла;
- автоматическое создание облачной папки, если она отсутствует;
- проверка OAuth-токена перед началом работы;
- продолжение работы после временных сетевых ошибок и ошибок чтения файлов;
- запись успешных операций и ошибок в лог;
- безопасное хранение настроек в `.env`, который исключён из Git;
- остановка программы сочетанием `Ctrl+C`.

В соответствии с техническим заданием программа работает только с файлами,
которые находятся непосредственно в отслеживаемой папке. Вложенные папки не
синхронизируются.

## Структура проекта

```text
file_synchronizer/
├── main.py                 # настройки и алгоритм синхронизации
├── yandex_disk.py          # коннектор к REST API Яндекс Диска
├── tests/
│   └── test_sync.py        # автоматические тесты бизнес-логики
├── .env.example            # пример настроек без настоящего токена
├── .gitignore
├── requirements.txt
└── README.md
```

Логика конкретного облачного сервиса изолирована в классе `YandexDisk`.
Основной алгоритм работает с интерфейсом `CloudConnector`, поэтому в дальнейшем
можно добавить коннектор другого хранилища без переписывания синхронизации.

## Требования

- Python 3.10 или новее;
- аккаунт Яндекса;
- OAuth-токен с доступом к Яндекс Диску;
- интернет-соединение.

Используемые сторонние библиотеки:

- `requests` — HTTP-запросы к REST API Яндекс Диска;
- `python-dotenv` — чтение настроек из `.env`;
- `loguru` — ведение журнала работы программы.

## Установка и запуск на Windows

Склонируйте репозиторий и перейдите в папку проекта:

```powershell
git clone https://github.com/DArtskr89/file-synchronizer.git
cd file-synchronizer
```

Создайте и активируйте виртуальное окружение:

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
```

Если PowerShell запрещает активацию, выполните эту команду только для текущего
окна терминала, а затем повторите активацию:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

Установите зависимости:

```powershell
python -m pip install -r requirements.txt
```

Создайте `.env` из примера:

```powershell
Copy-Item .env.example .env
```

Откройте `.env` и заполните настройки:

```dotenv
LOCAL_FOLDER=C:/Users/YourName/Documents/sync_folder
CLOUD_FOLDER=backup
YANDEX_TOKEN=your_token_here
SYNC_INTERVAL=10
LOG_FILE=logs/synchronizer.log
```

| Параметр | Описание |
| --- | --- |
| `LOCAL_FOLDER` | Полный путь к существующей локальной папке |
| `CLOUD_FOLDER` | Имя отдельной папки на Яндекс Диске |
| `YANDEX_TOKEN` | Секретный OAuth-токен Яндекс Диска |
| `SYNC_INTERVAL` | Интервал между проверками в секундах |
| `LOG_FILE` | Путь к файлу журнала |

Настоящий токен нельзя публиковать, добавлять в коммиты или показывать на
видеозаписи. Файл `.env` уже находится в `.gitignore`.

Запустите программу:

```powershell
python main.py
```

Первая синхронизация начинается сразу. Для остановки нажмите `Ctrl+C`.

> **Внимание:** используйте отдельную облачную папку для проекта. Программа
> приводит её содержимое в соответствие с локальной папкой и удаляет из неё
> файлы, отсутствующие локально.

## Запуск тестов

Тесты запускаются без настоящего Яндекс Диска и без доступа к интернету:

```powershell
python -m unittest discover -s tests -v
```

Проверяются следующие сценарии:

1. новый локальный файл загружается в облако;
2. изменённый локальный файл перезаписывается;
3. удалённый локальный файл удаляется из облака;
4. неизменённый файл повторно не загружается.

## Обработка ошибок

- при отсутствии локальной папки программа завершается с понятным сообщением;
- при пустых или неверных настройках указывается проблемный параметр;
- при неправильном токене выводится просьба проверить `YANDEX_TOKEN`;
- сетевые ошибки и ошибки доступа к отдельным файлам записываются в лог и не
  останавливают дальнейшую работу программы;
- нажатие `Ctrl+C` корректно завершает программу.

Пример формата журнала:

```text
synchroniser 2026-08-29 14:00:00,000 INFO Программа синхронизации файлов начинает работу с директорией C:/sync
synchroniser 2026-08-29 14:00:01,000 INFO Файл example.txt успешно записан.
synchroniser 2026-08-29 14:00:11,000 INFO Файл example.txt успешно перезаписан.
synchroniser 2026-08-29 14:00:21,000 ERROR Файл example.txt не синхронизирован. Ошибка соединения.
```

## База данных, миграции и фикстуры

В этом проекте база данных не используется: по техническому заданию источником
данных является локальная файловая система, а хранилищем резервных копий —
Яндекс Диск. Поэтому инициализация базы данных, миграции и загрузка тестовых
данных через фикстуры для данного сервиса не требуются.

Автоматические тесты создают временные файлы средствами стандартной библиотеки
Python и используют тестовый объект облачного хранилища `FakeCloud`. Реальные
пользовательские файлы и OAuth-токен во время тестирования не задействуются.

## Сценарий демонстрации проекта

Для финальной видеодемонстрации необходимо показать:

1. структуру проекта и отсутствие `.env` в публичном репозитории;
2. установку зависимостей и запуск автоматических тестов;
3. запуск `python main.py` и появление начальной записи в логе;
4. добавление нового файла в локальную папку и его появление на Яндекс Диске;
5. изменение файла и обновление облачной версии;
6. удаление файла и удаление его облачной копии;
7. ошибку при неправильном пути к локальной папке;
8. ошибку при неправильном токене, не показывая настоящий токен;
9. временную сетевую ошибку и запись `ERROR` в журнал;
10. корректную остановку приложения с помощью `Ctrl+C`.

Контейнеры, веб-интерфейс, Swagger и пользовательская
аутентификация/авторизация в приложении отсутствуют, поскольку они не входят в
техническое задание. Для доступа к облаку применяется OAuth-токен Яндекс Диска.
